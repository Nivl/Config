# take-over Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `take-over` skill that finishes a teammate's open PR for a Jira ticket, reusing `work-on`'s validation and tail, and give `work-on` the shared `wt` worktree preflight.

**Architecture:** `take-over/SKILL.md` is a delta document. It tells the run to read `work-on/SKILL.md` (never invoke it through the Skill tool) and follow its steps with named deltas. It owns the rebase, the implementation check and the PR edit outright. Shared behavior goes into `work-on` once: the worktree preflight, the `--branch` pass to `review-and-fix`, and a takeover rule in the validation lenses.

**Tech Stack:** Markdown skill files, one workflow script embedded in `VALIDATION.md`, one Python hook with a bash test.

**Spec:** `docs/superpowers/specs/2026-10-15-take-over-design.md`

## Global Constraints

- Skills live under `shared_config/.claude/skills/`. The new skill is `shared_config/.claude/skills/take-over/SKILL.md`.
- `take-over` reads `work-on/SKILL.md` and its helpers by path. It never invokes `work-on` via the Skill tool.
- Flags: `--no-assess`, `--fast`, `--assess`, `--review-limit`, `--full`, `--ab-model`, with `work-on`'s meanings. Review is uncapped by default.
- Force-pushes use `--force-with-lease`. A lease rejection stops the run. No automatic refetch and retry.
- Jira for `take-over`: assign to the user, never change status. Sprint only when in no active sprint.
- PR for `take-over`: never change draft or ready state. Edit title and body only where they break convention or no longer describe the diff.
- Ticket-key branch match is case-insensitive and respects digit boundaries.
- Prose follows AGENTS.md: plain ASCII, one thought per sentence, no ticket numbers in code comments.
- Commits in this repo: `PROSE_CLAIMS_OK=1 CASE_LIST_OK=1 CODE_CHECKS_OK=1 git commit ...`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Verification greps are wrap-tolerant: skill prose is hand-wrapped, so use `rg -U` with `\s+` between words, or single tokens.

## Review Focus

1. **Local branch already exists with commits the remote lacks.** Expected: stop, name the commits. Never push them onto the teammate's branch. Pinned in Task 2.
2. **Key that is a digit-prefix of another (`GRO-12` vs `gro-123-foo`).** Expected: no match, so a worktree opens. Pinned in Task 2.
3. **Teammate pushed after the fetch.** Expected: `--force-with-lease` rejects, the run stops and says so. Pinned in Task 5.
4. **PR from a fork, or zero PRs, or several.** Expected: stop and say so / stop and suggest `/work-on` / ask which one. Pinned in Task 4.
5. **`--assess` on a branch behind main.** Expected: no rebase, no push. The implementation check reads the branch as is and says it was not rebased. Pinned in Task 5.
