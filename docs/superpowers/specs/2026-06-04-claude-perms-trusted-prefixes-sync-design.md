# Sync the bash-allow hook data with `claude perms`

- **Date:** 2026-06-04
- **Status:** Design approved; pending implementation plan
- **Topic:** Make `bash-allow-trusted.py`'s trusted/excluded data a derived
  projection of `settings.json`, managed by `melvin-config claude perms`, and
  add a `perms exclude` subcommand for `sandbox.excludedCommands`.

## Problem

`bash-allow-trusted.py` decides which sandbox-**excluded** commands may run
without a prompt (excluded commands run unsandboxed, where `permissions.allow`
rules do not suppress prompts). Today the hook carries that knowledge as
**hardcoded Python literals** — `TRUSTED_PREFIXES`, `EXCLUDED_LEADERS`, and a
git-specific `READONLY_GIT` set. Three problems:

1. The literals drift from `settings.json`. Allow-listing `gh pr view *` does
   nothing until someone hand-edits the hook too.
2. `READONLY_GIT` (a set of git *subcommands*) cannot express dual-use forms:
   `git symbolic-ref --short` reads, `git symbolic-ref <ref>` writes. Several
   allow-listed git reads (`branch --show-current`, `apply --check`,
   `check-ignore -v`, `remote show`) are safe only in a specific
   subcommand+flag *form* a subcommand set can't capture.
3. There is no CLI to manage `sandbox.excludedCommands`; it is hand-edited.

## Goals

- The hook's trusted/excluded data is **derived from `settings.json`**, never
  hand-maintained.
- `claude perms allow|ask|deny add/remove` regenerates that data automatically.
- A new `claude perms exclude add/remove` manages `sandbox.excludedCommands`
  (with the same PATH-twin expansion as `--bash`) and regenerates the data.
- Regeneration is idempotent, so it doubles as the one-time **audit/migration**
  that backfills the data from the current `settings.json`.
- Drop `READONLY_GIT` and all git special-casing — git becomes ordinary
  prefixes.

## Non-goals

- No glob engine in Go or Python. All matching is whole-token prefix matching
  over token-tuples.
- No auto-coverage of git reads beyond what is allow-listed.
- No split-hint for mid-token glob exclusions (`rush db*`); those just prompt.

## Design

### One derived data file, two prefix lists, one matcher

`shared_config/.claude/hooks/bash-allow-trusted.json`:

```json
{
  "excluded": [["git"], ["gh"], ["docker"], ["go","get"], ["go","mod"],
               ["rushx","test"], ["rush","test"], ["rush","db"]],
  "trusted":  [["git","--no-pager","grep"], ["git","symbolic-ref","--short"],
               ["gh","pr","view"], ["rushx","test"], ["docker","compose"]]
}
```

Both lists are arrays of token-tuples. The leading token is **basename-
normalized**, so `gh *` and `/opt/homebrew/bin/gh *` collapse to `["gh"]`. The
file is generated by `perms`; a hand-edit is overwritten on the next run.

### Local override — `bash-allow-trusted.local.json`

A sibling `shared_config/.claude/hooks/bash-allow-trusted.local.json`,
**gitignored**, lets one machine add trusted/excluded prefixes that are *not*
committed to the shared dotfiles (e.g. work-specific `rushx`/`rush` entries).
Same `{excluded, trusted}` shape. The hook **unions** it over the committed
file — additive only: both `excluded` and `trusted` are merged and deduped;
there is no remove/override semantics. The Go `perms` command neither reads nor
writes this file and is entirely unaware of it — it only ever (re)generates the
committed `bash-allow-trusted.json`. So `perms` regeneration never clobbers
local entries, and `git add bash-allow-trusted.json` never touches the
gitignored local file.

**Matching** (`prefix_match(prefix, tokens)`): let
`head = [basename(tokens[0])] + tokens[1:]`; true iff `len(head) >= len(prefix)`
and `head[:len(prefix)] == prefix`. Then `is_excluded` = any `excluded` prefix
matches; `is_trusted` = any `trusted` prefix matches. This is injection-safe:
`git -c core.pager=evil grep` shifts the tokens so it matches no `trusted`
prefix (token 2 is `-c`, not `grep`), and `git -C /x …` is denied by
`git-deny-dash-c.py` regardless.

### Hook refactor — `bash-allow-trusted.py`

- At startup, load and **union** two files into `EXCLUDED` / `TRUSTED`:
  `bash-allow-trusted.json` (committed) and `bash-allow-trusted.local.json`
  (gitignored, optional). Each file is read defensively — missing or malformed
  → contributes nothing, never a crash. The two `excluded` lists are
  concatenated and then **fully deduped by tuple value**, and likewise for
  `trusted` — a tuple appearing in both files, or repeated within one (the
  hand-maintained local file may contain either), collapses to a single entry.
  If neither file yields anything,
  the hook is inert and every command falls through to the normal permission
  flow (**fail closed**: nothing trusted, nothing denied, never an
  over-allow).
- Delete `READONLY_GIT`, `is_readonly_git`, `SAFE_GIT_GLOBAL_FLAGS`, and the
  hardcoded `TRUSTED_PREFIXES` / `EXCLUDED_LEADERS`. `is_excluded` / `is_trusted`
  become the two-line `prefix_match` checks above.
- Decision logic is otherwise unchanged:
  1. compound (`|`, `&&`, `||`, `;`, `&`, newline) AND any segment `is_excluded`
     → **deny** with the split-into-two-commands guidance.
  2. single command, first segment `is_trusted`, redirects safe → **allow**.
  3. otherwise silent.
- `has_unsafe_write_redirect` (the `> file` must be under a write root) is
  unchanged.

### Derivation — new `internal/claude/perms` code

`toPrefix(s string) []string`: strip a trailing ` *`, `*`, or `:*`; peel
leading `FOO=bar` env assignments; split on whitespace; basename the first
token. Non-Bash allow rules (`Read(...)`, `WebFetch(...)`, `Skill(...)`) are
skipped. A leading-`*` rule (`* --version`) yields `["*","--version"]`, which
matches no excluded prefix and is therefore dropped from `trusted`.

`Derive(allow, excluded []string) (trusted, excludedPrefixes [][]string)`:
- `excludedPrefixes` = `toPrefix` of each `sandbox.excludedCommands` entry,
  sorted + deduped.
- `trusted` = for each `permissions.allow` entry, unwrap `Bash(...)`,
  `T = toPrefix(inner)`, keep `T` iff some `E ∈ excludedPrefixes` is a prefix of
  `T` (`E == T[:len(E)]`). Sorted + deduped. That prefix test *is* the
  "allowed ∩ excluded" relation.

`WriteBashAllow(path string, trusted, excluded [][]string) error`: marshal
`{excluded, trusted}` with stable ordering, 2-space indent, trailing newline.

### Settings extension — `internal/claude/perms/settings.go`

`Settings` already round-trips every top-level key as raw JSON. Extend it to
model the excluded list: parse `top["sandbox"].excludedCommands` into a typed
`[]string`, keep the remaining `sandbox` keys in a `sandboxOther` map (mirroring
`permsOther`), and rebuild `sandbox` on `Save`. Expose
`ExcludedCommands() []string` and `SetExcludedCommands([]string)`. When no
`sandbox` key exists, the list is empty and `Save` adds nothing.

### cmd layer — `internal/cmd/claude_perms.go`

- New `perms exclude` parent with `add` / `remove` children. Patterns are raw
  command globs supplied as **positional args** (`perms exclude add "gh *"
  "docker *"`, `cobra.MinimumNArgs(1)`) — `exclude` has only one input kind, so
  it needs no `--bash`/`--read`-style flags. Expansion reuses `bashVariants` so
  `gh *` also yields `/opt/homebrew/bin/gh *`. This is a parallel flow to
  allow/ask/deny because
  the target lives under `sandbox`, not `permissions` — it shares variant
  expansion, the regenerate step, and the commit, but not `ListName`/`Add`.
- **After any mutation** (allow/ask/deny add/remove OR exclude add/remove),
  regenerate `bash-allow-trusted.json` from the in-memory `Settings`
  (`Derive(allow, excluded)` → `WriteBashAllow`), then `git add` **both**
  `settings.json` and `bash-allow-trusted.json` in the one commit. Dry-run
  reports both files.
- Audit/migration (requirement 1): regeneration is idempotent, so the first
  real `perms` invocation backfills the file. The implementation commit also
  checks in the generated file built from the current `settings.json`.

### Behavior consequences (intended)

- Every allow-listed **excluded** command becomes auto-allowed **when run
  alone**, including allow-listed git *writes* (`git add *`, `git mv *`,
  `git rm *`, `git stash *`, `git pull *`, `git merge origin/* *`,
  `git cherry-pick *`, `git fetch *`). `git push` / `commit` / `reset` are not
  in `permissions.allow`, so they keep prompting.
- Git read coverage now equals exactly the allow-listed git reads. A read not
  allow-listed (e.g. `git cat-file`) now prompts instead of being auto-covered
  by the old broad `READONLY_GIT` — the more precise behavior for this setup.

### Edge cases

- Mid-token glob exclusion `rush db*` → `["rush","db"]`, which matches `rush db`
  but not `rush db:migrate:up` (one token `db:migrate:up`). Whole-command rules
  (`… *`, `…:*`, exact) map perfectly. The compound form of a mid-token case
  just prompts rather than getting the split-hint.
- Missing/corrupt JSON → hook fails closed (above).

## Testing

- **Go:** `toPrefix` (trailing `*`/`:*`/exact, env peel, path basename,
  leading-`*`); `Derive` (gh view/list kept, `go build` dropped, git writes
  kept, path-twin collapse, dedupe/sort); `Settings` excluded round-trip with
  other `sandbox` keys preserved; `exclude add/remove`; regenerate writes the
  JSON and the commit stages both files; dry-run touches nothing.
- **Python:** `prefix_match`; lone-trusted allow; compound-excluded deny;
  write-redirect bail in/out of roots; committed+local **union** (local adds a
  trusted and an excluded entry that then take effect); local file absent (uses
  committed only); local file malformed (ignored, committed still applies);
  both files missing → fail-closed.
